# Receipt terminal fold extractor

This directory is a standalone Roslyn-to-Lean package for the normal standard-mainnet terminal path of the exact base `BlockReceiptsTracer` (`parallel=false`, with no `BuildReceipt` override). It admits the receipt projection, cumulative-gas update, terminal forwarding order, normal-prefix snapshot restore, and the caller's separate `TransactionResult` classification without changing Nethermind production code. It makes no claim about receipt Bloom/RLP/trie/root computation, state-root correctness, or receipt/database persistence.

The extractor binds the selected C# members with Roslyn syntax and symbols, checks pinned source fingerprints, complete canonical member admissions, and ordered semantic anchors, then records Roslyn-derived syntax terms plus resolved symbol identities, converted types, and typed invocation/assignment/guard facts for each admitted operation and projection. Compilation uses the runtime-platform entries from the trusted platform assembly list plus the release production/dependency closure (`Nethermind.Init`, the Evm bundle, and the `Nethermind.Network.Enr.Test` dependency bundle). The admitted `TransactionProcessor.cs` and `TransactionExtensions.cs` units are compiled as their actual production source units; no extractor-owned containing type or synthetic no-op member is substituted. `COMPILER_REFERENCE_PINS.json` is the checked-in, canonical inventory of that closure: its own bytes, exact 434-path set, count, aggregate digest, per-file SHA-256/MVID, metadata validity, and one selected path per assembly are pinned before any extraction output can be written; additions, removals, and byte drift fail closed. Host-specific application assemblies are excluded from the platform portion because the release closure supplies all non-framework dependencies. The full compilation diagnostic set is materialized and errors fail extraction, followed by a complete source-tree candidate/error-symbol scan. Every modeled operation rejects candidate/ambiguous bindings, invalid or unresolved operations, `IErrorTypeSymbol` in declarations, receivers, returns, parameters, conversions, and operation types, and missing metadata. A structural lowerer consumes those facts (including source arguments, state assignments, source order, receipt initializer expressions, guards, status literals, and caller result/output expressions) to produce three deterministic artifacts under `Generated/`; unsupported or unbound syntax fails closed instead of falling back to an unrelated template. The focused test-only source-mutation path skips only immutable source/member hashes, reuses the real production reference root, and must produce a changed, Lean-checked artifact; normal extraction always enforces the immutable admissions. `--check --repo-root <root>` performs the pinned inventory and checked-in artifact gate without regenerating outputs, and `Verify.ps1` runs it before scratch extraction and after all checks; verification never rewrites the checked-in artifacts or compiler pins.

* `ReceiptTerminalFoldKernel.ir.json` — typed syntax/semantic extraction IR;
* `ReceiptTerminalFoldKernel.source-manifest.json` — source, member, delegated-kernel, and artifact identities;
* `ReceiptTerminalFoldKernel.lean` — theorem-free generated transition model.

The generated model calls the existing `Eip803x.Generated.BlockReceiptGasAccountingKernel` for all three cumulative additions and the header maximum. Diagnostic receipt fields are concrete natural numbers with zero defaults, matching the nonnullable production `ulong` properties and their guarded assignments. Its `TransactionInput` contains `to` but no independent creation flag: `isContractCreation` is derived from `to.isNone`, while the extractor separately admits the production `Transaction.IsContractCreation => To is null` relation. The exact-base `IsTracingReceipt => true` source pin discharges the caller's outer receipt gate; the two model booleans only describe nested-tracer presence and current-transaction-tracer forwarding. In the live caller (source SHA `0374c6f35a9a23361f37b41162ac281ca83b09846ab4295d5a592db6315c99cc`), the `BuildUp && IsEip8037Enabled` branch performs `ResetTransient` then `ReapEmptyAccounts` before the receipt gate; this ordered world-state cleanup is admitted as an upstream effect but remains outside the terminal fold's state model. Finalization uses one `substate.Output` oracle for both success forwarding and revert-failure forwarding (non-revert failure forwards empty), then returns a combined observation containing the terminal trace and a result that distinguishes revert/failure with `TransactionResult.Ok` from exceptional failure with `TransactionResult.EvmException` and `SubstateError`; its total `vmError` oracle represents the source's total `FastToString()` fallback and is ignored when no exception exists. The independent handwritten reference uses a terminal-decision fold in `Specification/ReceiptTerminalFold.lean`; the refinement has a universal internal generated/reference equality and a domain-restricted theorem with `ProductionFinalizeDomain`, alongside exact append, caller-result, and normal-prefix restore theorems in `Refinement/ReceiptTerminalFold.lean`; executable proof-checked cases are in `Vectors/ReceiptTerminalFoldVectors.lean`.

The manifest records thirty-eight binding-closure source files separately from the twelve transition sources. They include the tracer/state interfaces, journal collection, option flags, world-state/spec interfaces, null tracer, substate, exception, output-conversion declarations, and the standard `Transaction` partial implementation needed to resolve every modeled symbol. The standard Transaction partial and extensions compile together; BlockBody supplies Block's internal setter; the caller and gas-policy groups include their real interfaces, partials and internal helpers. The full pinned VirtualMachine source contributes only its unchanged `VirtualMachineStatics` declaration and bodies, selected structurally without a substitute member. `SOURCE_PINS.json` is consumed and cross-checked against the extractor's twelve/thirty-eight path and hash tables. The compiler inventory records the ordered closure, all 434 logical paths, each assembly name, SHA-256 and MVID, and exactly one selected path for each of the 329 assembly names, plus its count and aggregate digest. Removing, adding, or replacing a release assembly, dependency bundle, trusted platform assembly, or metadata file therefore fails before semantic lowering rather than silently producing error symbols. The consensus-side `TransactionProcessorAdapterExtensions.ProcessTransaction` wrapper and the later block `ProcessTransactions` orchestration remain outside this terminal claim; their normal-return handoff is a future typed adapter boundary.

From the repository root, the complete package gate is:

```powershell
pwsh tools/Evm/Lean/ReceiptTerminalFoldExtractor/Verify.ps1
```

The gate builds the pinned Release metadata closure and extractor with `SOURCE_DATE_EPOCH=1789035784`, validates the checked-in compiler inventory and artifacts, extracts twice into private temporary directories, compares all artifact hashes, and runs `lake --wfail build` plus four direct warning-as-error Lean targets. `DECLARED_THEOREMS.txt` freezes the twelve named claims; `EXPORTED_THEOREMS.txt` freezes all 234 public theorem constants in the specification/refinement/vector namespaces, including compiler-generated equation lemmas. Source declarations and Lean's loaded environment must match those inventories, then `Lean.collectAxioms` verifies every exported theorem uses only `propext`, `Classical.choice`, or `Quot.sound`. Missing results, missing exports, extra exports and an injected forbidden axiom are negative controls. The final extractor `--check` confirms no artifact drift. ## Controlled admission refresh

Schema 9 records source statement/expression positions and every enclosing `if` condition and true/false arm, in outer-to-inner order. The statement and guard trees must agree with each other and with every invocation/assignment path. Each fact must identify its actual typed source effect, so forging a position into an empty arm cannot detach the effect from its branch. The emitter separately admits the polarity and nesting used by each lowered effect; moving forwarding, diagnostic, rollback or finalization effects into an `else` arm fails with a named branch diagnostic. Calls in an `if` condition are not treated as effects of its own true arm; conditional-expression semantics remain in the expression tree.

Extractor 1.9.2 additionally admits the complete statement layout of all thirteen modeled methods. Eight operation trees are checked during IR lowering, and the five dependency methods are checked in the bound source. The closed grammar fixes the number, order and nesting of statements and branches, including the sole terminal return in each block-bodied value method. Extra returns, throws, jumps, loops, exception handlers, deferred bodies and unsupported branches fail `RECEIPT_CONTROL_FLOW`; ordered nonoverlapping statement ranges prevent a serialized tree from presenting a different execution order. This closes the earlier-exit gap that enclosing branch facts alone cannot detect. The control-flow gate does not broaden the published normal-return and callback-totality boundary.

The shared effect ledger exhausts every admitted method's calls, writes, local initializers and allocations, including nested expressions and writable arguments. Both source statements and serialized facts must agree completely; unknown or omitted effects fail `RECEIPT_EFFECT_LEDGER`. `BuildReceipt` and `BuildFailedReceipt` must return the exact local symbol initialized by their admitted construction, enforced by `RECEIPT_RETURN_BINDING`. Compile-valid source controls cover all thirteen methods, and coordinated IR controls change both retained trees and effect facts. The existing value-mutation controls likewise update the source trees and facts together before checking that the independent Lean refinement rejects the changed semantics.

Artifact publication stages and disk-flushes all changed files in their destination directories before replacing any destination. Each existing file is replaced through `File.Replace`, and the source manifest is published last. This is per-file replacement, not an atomic three-file transaction: an interrupted batch can leave complete files from different generations, which exact validation rejects. Observed failures/cancellation clean up staged files and preserve unpublished destinations; hard process termination can leave unreferenced temporary files, never accepted as artifacts. Filesystem crash recovery and power-loss guarantees remain outside the Lean claim.

Normal extraction and verification never refresh source or compiler admission. To admit a changed build, first build both closure projects at the pinned source epoch, then review the complete inventory diff (including unselected duplicate paths), the assembly selections and every SHA-256/MVID change. Update schema-2 `COMPILER_REFERENCE_PINS.json` and its three explicit count/aggregate/file-hash pins in `ReceiptTerminalFoldProfile.cs` together. Refresh a source pin only after reviewing that source's behavior and all affected member admissions. Run the extractor with explicit `--output` and `--lean-output` paths to regenerate the schema-9 artifacts; generation still enforces every source, compiler and delegated-kernel admission before writing anything. Run the package gate and independent review before accepting the refresh.

The delegated Lean closure is pinned transitively in schema-3 `SOURCE_PINS.json` and the schema-9 source manifest: the accounting generated/refinement files, `BlockReceiptGas`, `TransactionGas`, and the generated/refinement transaction-initialization files. Each of the six files has missing-file and byte-drift controls, and a test checks the inventory equals the complete local import closure. This prevents a changed imported specification from being silently accepted under an unchanged top-level proof file.
