# Test plan

`Test/ReceiptTerminalFoldExtractorTests.cs` is a non-parallel focused suite.

* Effect completeness and return binding: two compile-valid builder-return substitutions and two `Debug.Assert`-to-`_txReceipts.Clear()` substitutions reproduced successful extraction before the fix. The corrected gates require the constructed receipt's exact returned local and exhaust all calls/writes/initializers/allocations. Eleven additional compile-valid controls cover every remaining admitted method. Two coordinated IR return controls, four coordinated call/write controls, and two omitted-fact controls exercise the serialized boundary. A compile-valid source control and a coordinated IR control also reject conditional construction that can leave the returned local null. Each negative requires its exact `RECEIPT_RETURN_BINDING` or `RECEIPT_EFFECT_LEDGER` diagnostic. The existing semantic mutations now coordinate statement trees, branch trees and typed facts before testing changed Lean against the independent refinement.

* Control flow: sixteen compile-valid source insertions and sixteen coordinated IR insertions put early returns before receipt append, both forwarding surfaces, receipt construction and diagnostics, cumulative-gas history, snapshot, restore, legacy state-root calculation, fallback error selection, and both terminal callbacks. Both IR trees are updated together, leaving effect positions and existing branch facts intact. All 32 regressions failed against the pre-fix extractor and pass with `RECEIPT_CONTROL_FLOW` after the fix. Five further compile-valid source cases cover the accounting, gas-combine and price dependencies; eight cases reject throw statements/expressions, loops, jumps, exception handlers and extra branches. Each negative requires the named control-flow diagnostic after complete Roslyn compilation, so an earlier pin or binding failure cannot stand in for the intended gate.

* Branch polarity: eight compile-valid source arm flips cover both forwarding methods, block/state diagnostic writes, header accounting, restore removals, finalization error fallback and legacy state-root assignment. Each must reach `RECEIPT_BRANCH_POLARITY`. The same eight serialized-IR cases change both retained trees with three variants: stale path facts (`RECEIPT_BRANCH_PATH`), matching false-arm facts (`RECEIPT_BRANCH_POLARITY`), and positions forged into the empty true arm (`RECEIPT_BRANCH_PATH`). A forwarding-order fact moved outside its source branch is now rejected before emission. Two malformed guard/declaration-source controls require explicit shape diagnostics before tree comparison.
* Publication: an open reader retains the complete old file across replacement; interruption and I/O injection before each of the three publications preserve complete files and the old manifest, remove staged files, and allow retry. Real staging and replacement failures preserve unpublished destinations. The tests do not claim a three-file atomic transaction or power-loss durability.

* Determinism: two fresh extractions must have byte-identical IR, manifest, and Lean; checked-in artifacts must match a fresh extraction.
* Admission completeness: the test asserts twelve transition source files plus thirty-eight pinned binding-closure source files, 56 bound members (including complete canonical method fingerprints, the exact-base receipt-gate property, and the live status/combine closure), eight ordered operations, seventeen mappings, and all gas/receipt/transaction/block/header/finalization field counts; transaction creation is derived from `to` in both models. The standard `Transaction` partial support is compiled with its transition source, and the caller/extension units are compiled as their actual production source units rather than extractor-owned adapters.
* Generated surface: generated Lean is theorem-free, imports the identity-pinned accounting kernel, contains success/failure/restore transitions, and has no `ReturnValue` assignment.
* Typed artifact robustness: operator/order, mapping, scope, field/effect lowering escapes, member-identity, aggregate, delegated-kernel, unknown-property, duplicate-property, malformed/canonical JSON mutations, operation input/output contracts, receipt/forwarding payload linkage, receipt-status linkage, mismatched success/failure forwarding guards, non-empty collection literals, and an unsupported operation-body expression are rejected. Eight type-preserving semantic-IR mutations (accounting argument, restore argument and assignment, receipt field, terminal payload, status literal, failure-error source, and returned error source) must change the emitted Lean and each changed file is checked with `lake env lean`; the same eight mutations are then installed as isolated replacement generated modules and must fail in the copied independent refinement/vector graph, with diagnostics tied to that graph rather than merely to generated-module typechecking. Two source mutations remain positive rebinding cases and are re-bound through Roslyn into typed IR and then lowered to changed, Lean-checked artifacts; six additional source mutations introduce unknown methods/types and must fail on complete compilation diagnostics, while restore-prefix and caller-gate source guard mutations must fail in typed lowering and complete compiler-tree candidate/error-symbol scans guard the unmodeled source. The test-only path skips only immutable source/member hashes and reuses the real production reference root.
* Source/reference robustness: missing sources plus source/operator/order mutations of the sequential guard, receipt append, unchecked accounting addition, failure-output guard, status constants, both live block-gas combine closure members, and the admitted EIP-8037 account-reap ordering are rejected by the source pins and canonical admissions. Clearing the trusted-platform metadata input is rejected before binding. The compiler gate requires the checked-in inventory bytes, exact runtime-platform and three release-directory path set, every required production/dependency assembly, valid metadata, per-file digest, and count/aggregate digest; additions, removals, or byte drift fail before any output write.

`Vectors/ReceiptTerminalFoldVectors.lean` executes success, ordinary failure/revert, exceptional failure, and a retained-prefix restore. Every listed observation is a kernel-decided proposition; the file also instantiates the domain-restricted finalization refinement with explicit `AccountingValid`, sequentiality, and `ProductionFinalizeDomain` witnesses. The exact-base `IsTracingReceipt => true` premise is source-pinned by the extractor admission and is not presented as a separately constructed vector witness. It checks paid-gas accumulation, block-header maximum, concrete zero-default diagnostics, the shared success/revert output oracle and non-revert empty-output guard, empty failure logs, error precedence, creation address placement, distinct receipt-status/result classification, total exception fallback, and prefix reset, and prints the resulting observations with `#eval`.

The package gate is `Verify.ps1`. It runs warning-as-error .NET builds, validates the checked-in inventory without changing it, and runs at least 180 focused test cases, two scratch extractions and hash comparisons (including the compiler-reference identities), `lake --wfail build`, and direct warning-as-error Lean checks for generated, specification, refinement, and vector modules.

The compiler inventory also rejects duplicate paths, missing or duplicate assembly selections, malformed and empty MVIDs, malformed digests, and moving a required selection to the wrong production path. The twelve named claims and all 234 public theorem constants in the specification/refinement/vector namespaces (including compiler-generated equation lemmas) have separate frozen inventories and a `Lean.collectAxioms` gate; only the three standard axioms are allowed, and missing/extra/forbidden cases must fail. Vectors use kernel `decide` rather than native compilation as proof evidence.

The delegated Lean closure is pinned transitively in schema-3 `SOURCE_PINS.json` and the schema-9 source manifest: the accounting generated/refinement files, `BlockReceiptGas`, `TransactionGas`, and the generated/refinement transaction-initialization files. Each of the six files has missing-file and byte-drift controls, and a test checks the inventory equals the complete local import closure. This prevents a changed imported specification from being silently accepted under an unchanged top-level proof file.
