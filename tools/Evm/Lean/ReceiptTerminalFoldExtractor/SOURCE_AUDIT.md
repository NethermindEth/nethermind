# Source audit

`ReceiptTerminalFoldEffects` validates all thirteen bound methods and the eight serialized operations with the same exhaustive call/write/initializer/allocation ledger. It traverses the complete admitted expression grammar and rejects unconsumed expression kinds, writable arguments, extra or missing effects, and detached facts. Both receipt builders additionally bind the terminal return's local symbol to the source construction's local symbol. The compile-valid `return null!` and `Debug.Assert`-to-`_txReceipts.Clear()` substitutions previously extracted successfully; the named return/effect gates now reject them. The remaining method controls and coordinated IR return/call/write controls exercise the same shared admission without relying on source hashes.

`ReceiptTerminalFoldControlFlow` admits the complete ordered statement layout of all thirteen modeled methods. For the eight lowered operations this runs on the retained IR statement tree after branch-path/polarity validation; the five dependency methods use the same admission on their bound source trees. Every accepted block-bodied value method has exactly one return at its end, and accepted void methods have no explicit return. Unsupported statements and exceptional/deferred expression bodies are rejected, and sibling statement ranges must follow source order without overlap. This prevents earlier control transfers from bypassing receipt, gas, forwarding, restore or terminal effects even if the retained guard trees and effect paths agree. The expression-bodied dependencies remain expression bodies. Called methods' normal-return and callback-totality assumptions remain part of the published boundary.

Schema-9 control-flow admission records each source statement range, expression position and ordered `if`-branch path with polarity. Both retained conditional trees and each fact's source position must agree; the position must identify the actual typed invocation or assignment, not merely an enclosing range. The emitter independently checks the admitted arms before using guards. The eight source-arm flips and coordinated serialized-tree/fact mutations, including forged positions into empty arms, exercise forwarding, sibling diagnostic writes, restore, and finalization paths.

Publication uses disk-flushed same-directory staging, then replaces each destination, with the manifest last. Existing-file replacement follows [.NET's `File.Replace` contract](https://learn.microsoft.com/en-us/dotnet/api/system.io.file.replace?view=net-10.0). No multi-file atomicity, directory-metadata durability, or filesystem correctness theorem is claimed; mixed generations fail the exact artifact gate.

The compiler closure is not a source stub or a single Int256 package. It requires the runtime-platform entries from the trusted platform assembly list and these release directories under the repository root: `src/Nethermind/artifacts/bin/Nethermind.Init/release` (the production project closure), `tools/artifacts/bin/Evm/release` (the locked Evm dependency bundle), and `src/Nethermind/artifacts/bin/Nethermind.Network.Enr.Test/release` (the package bundle containing `Microsoft.Extensions.ObjectPool`, which `Transaction.cs` imports). Host-app entries that happen to be present in the trusted list are excluded; all non-framework dependencies are instead admitted from the three pinned release directories, making extraction independent of whether it runs as the executable or under the test host. `COMPILER_REFERENCE_PINS.json` is the checked-in canonical inventory for the runtime/platform and release closure: it records its own pinned bytes, the exact 434-entry path order, count, aggregate SHA-256, per-file SHA-256/MVID, and exactly one selected path for each of the 329 assembly names. Before any output write, extraction compares the live trusted-platform and release-directory path set with that inventory, rejects additions/removals, hashes every pinned file and rejects byte drift, and creates metadata references only from the verified inventory. Required production names include every project containing a modeled type plus `Nethermind.Int256`, and required dependency names include `Collections.Pooled` and `Microsoft.Extensions.ObjectPool`. A missing directory, required assembly, invalid metadata file, or missing trusted-platform list fails extraction. The caller and extension units are compiled as their actual production source units; the compiled support groups preserve source interfaces, partial implementations and internal helper bodies, while the remaining audited declarations are supplied by the exact verified metadata inventory. Complete compilation diagnostics and source-tree candidate/error-symbol scans fail extraction. `--check` validates this inventory and the checked-in artifacts without rewriting admission or artifacts; the source manifest repeats every logical path, assembly name, digest, MVID, selection, count, and aggregate, making the exact reference closure auditable.

The admitted member set is 56 exact members: thirteen methods with complete canonical-token fingerprints, three fields (the two live status constants plus the admitted header base-fee field), six `GasConsumed` primary parameters, and 34 properties (the exact-base receipt-gate property, two computed gas properties, 19 receipt properties including the explicitly excluded `ReturnValue`, six transaction properties, three block properties, and three remaining header properties). The IR has eight ordered operations, seventeen typed mappings, and nine typed finalization-input fields; its lowering consumes the admitted operations, mappings, receipt field order, and finalization field order rather than a detached Lean template. The generated transaction input contains `To` but no independent `IsContractCreation` oracle; the source-admitted `Transaction.IsContractCreation => To is null` relation is represented as a mapping and proved structurally in the refinement. The caller result is modeled separately from receipt status: `EvmExceptionType.None` maps to `TransactionResult.Ok`, while a non-None type maps to `TransactionResult.EvmException` with the source `SubstateError` payload. The one `substate.Output` input is reused for success and revert-failure forwarding; non-revert failure forwards empty. The live caller's `ResetTransient` followed by `ReapEmptyAccounts` under `BuildUp && IsEip8037Enabled` is source-admitted before the receipt gate as an upstream world-state effect, not claimed as part of the fold state.

Compiler-reference SHA-256, assembly name, MVID, and Roslyn metadata references are derived from the same captured byte image, not separate file opens. Each parsed binding-support source is also checked against its admitted digest before compilation. These checks keep the bytes used for binding identical to the bytes being admitted.

The checked-in generated artifacts are derived outputs, regenerated explicitly only after source, compiler and dependency admission succeeds. `Verify.ps1` never rewrites them. The regenerated source manifest records their exact byte digests together with every compiler-reference digest; `Verify.ps1` enforces the same bytes after two fresh extractions and runs the focused C# tests.

The C# source audit is implemented in `ReceiptTerminalFoldProfile.ValidateSourceSemantics`: it checks the exact base tracer declaration, `IsTracingReceipt => true`, and virtual base builder boundary; live status constants and the complete `EthereumGasPolicy`/`BlockGasAccountingKernel` combine closure; receipt-before-forwarding order; failure-log construction; three kernel additions; diagnostic guards with zero-default semantics; creation/message address split; restore order; error-source precedence; failure-output guard; success output forwarding; and zero-history defaults. It also binds the ordered `TransactionResult.EvmException`/`TransactionResult.Ok` return branches and `SubstateError` payload. The refinement keeps a universal internal generated/reference equality free of reachability premises; the public domain-restricted theorem adds the explicit reachable-finalize adapter obligation `ProductionFinalizeDomain` that successful status implies `EvmExceptionType.None`. `TransactionInput` derives `IsContractCreation` from `To`, so arbitrary inconsistent pairs are not representable in the model; proving the production `Transaction` projection into that model remains open. The ordinary failure/revert case remains status-failure plus `TransactionResult.Ok`. The total `vmError` input represents the source's total `EvmExceptionType.FastToString()` fallback and is used only for a non-None exception.

The C# audit materializes the complete Roslyn compilation diagnostic set and rejects any error, then scans every compiled source tree for candidate/ambiguous or error symbols. For each modeled member it also rejects invalid operations, unresolved required operation targets, and error symbols or `IErrorTypeSymbol` recursively in declarations, containing/receiver types, return types, parameter types, converted types, and operation types. The live caller's `ResetTransient` followed by `ReapEmptyAccounts` under `BuildUp && IsEip8037Enabled` is explicitly admitted before the receipt gate as an upstream effect; the terminal fold does not claim to model world-state cleanup or persistence. Roslyn's `OmittedArraySizeExpressionSyntax` node for the empty rank specifier in a valid array type is excluded from direct `TypeInfo` inspection; the contextual `nameof` identifier is excluded only when its enclosing invocation resolves to `INameOfOperation`, and Roslyn's omitted unbound-generic type arguments are excluded only for `INamedTypeSymbol.IsUnboundGenericType`. Enclosing types, declarations, conversions and operations remain validated. The consensus-side `TransactionProcessorAdapterExtensions.ProcessTransaction` wrapper and the block `ProcessTransactions` orchestration are not part of this source closure.

The delegated Lean closure is pinned transitively in schema-3 `SOURCE_PINS.json` and the schema-9 source manifest: the accounting generated/refinement files, `BlockReceiptGas`, `TransactionGas`, and the generated/refinement transaction-initialization files. Each of the six files has missing-file and byte-drift controls, and a test checks the inventory equals the complete local import closure. This prevents a changed imported specification from being silently accepted under an unchanged top-level proof file.
