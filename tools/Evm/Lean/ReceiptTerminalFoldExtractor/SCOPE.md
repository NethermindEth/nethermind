# Scope and trust boundary

## Claim

For a normal, sequential standard-mainnet exact base `BlockReceiptsTracer(parallel=false)` instance (no subclass `BuildReceipt` override), whose admitted `IsTracingReceipt => true` property discharges the caller's outer receipt gate, a normally returning `TransactionProcessorBase.FinalizeTransaction` terminal call is represented by the generated fold with the following receipt/result effects. The model's two forwarding booleans are only nested-tracer presence and the current transaction tracer's forwarding gate; they do not model an arbitrary outer tracer gate.

1. cumulative receipt gas and block execution/state totals are updated;
2. the sequential block header gas total is updated from the pinned accounting kernel;
3. a success or failure receipt is appended with the admitted receipt fields;
4. failure receipts have empty logs and carry the selected error;
5. nested/current tracer forwarding happens after receipt append and gas mutation;
6. a valid normal-prefix restore removes the receipt and block-gas suffix and recomputes retained totals;
7. the caller result is retained separately from receipt status: `EvmExceptionType.None` returns `TransactionResult.Ok`, while a non-None type returns `TransactionResult.EvmException` carrying `SubstateError`;
8. at the caller boundary, the live `BuildUp && IsEip8037Enabled` path performs `WorldState.ResetTransient` followed by `WorldState.ReapEmptyAccounts` before the receipt gate; this is source-admitted upstream ordering only, not a world-state effect represented by the fold.

The refinement is exact for the generated fixed-width transition under the hypotheses stated in the Lean file. The model has no independent creation flag: it structurally derives `IsContractCreation` from `To`, so the admitted transaction relation satisfies `IsContractCreation` iff `To` is null; the extractor separately source-admits that production relation, while the remaining production-object projection is explicitly open. The finalization theorem is domain-restricted by the reachable-finalize adapter obligation `ProductionFinalizeDomain`, which excludes successful status paired with a non-None exception. Its natural-number corollary assumes every input and intermediate addition fits `UInt64`; the generated transition retains the production kernel's unchecked `ulong` arithmetic exactly.

## Source binding

The extractor reads and identity-pins the selected members of `BlockReceiptsTracer`, `TransactionProcessorBase`, `GasConsumed`, `TxReceipt`, `Transaction`, `TransactionExtensions`, `Block`, `BlockHeader`, `StatusCode`, `EthereumGasPolicy`, `BlockGasAccountingKernel`, and `BlockReceiptGasAccountingKernel`. It also pins the thirty-eight-file Roslyn binding closure used to resolve every modeled receiver, method, member, and converted type. The source groups include the standard Transaction partial, transaction extensions, BlockBody, caller interfaces and internal helpers, and gas-policy helpers. The VirtualMachine binding file contributes the unchanged `VirtualMachineStatics` declaration, selected structurally with its production namespace, usings and all method bodies; the complete file is identity-pinned. These support declarations do not broaden the transition claim. The admitted `TransactionProcessor.cs` and `TransactionExtensions.cs` units are compiled as their actual production source units, so selected members cannot bind to extractor-owned containing types or synthetic no-op members. Every external symbol is resolved from the same complete production metadata closure. Roslyn compiles this source closure against the runtime-platform entries from the trusted platform list and the required release production/dependency directories (`Nethermind.Init`, the Evm bundle, and `Nethermind.Network.Enr.Test`). `COMPILER_REFERENCE_PINS.json` is the checked-in canonical inventory of that closure; before any artifact write or normal `--check`, its exact 434-path set, count, aggregate digest, per-file SHA-256/MVID, metadata validity, and one selected path per assembly are checked, and additions/removals/byte drift fail closed. The source manifest repeats that verified inventory. Host-specific application assemblies are excluded from the platform portion because the release closure supplies all non-framework dependencies. Every compiled source unit and modeled declaration rejects complete-diagnostic errors, candidate/ambiguous symbols, invalid or unresolved operations, and `IErrorTypeSymbol` recursively in containing/receiver, return, parameter, converted, and operation types. Roslyn syntax and semantic symbols are recorded in the manifest, and each modeled method has a complete canonical-token fingerprint in addition to its path/owner/signature admission. The IR retains canonical Roslyn expression/statement trees and typed invocation, assignment, guard, and return facts for every lowered operation/projection; the emitter structurally lowers those facts, including source call arguments, state assignments, statement order, receipt initializer expressions, diagnostic guards, status literals, and caller output/result expressions. Ordered source anchors admit receipt-before-forwarding, error precedence, output forwarding, diagnostic guards, recipient/contract-address selection, the EIP-8037 account-reap ordering, and the caller's terminal branch order; the live status/combine dependency closure is pinned rather than inherited from the delegated artifact manifest. A construct outside this lowering vocabulary is rejected during emission rather than silently replaced by a fixed transition body.

`BuildReceipt` deliberately does not model `TxReceipt.ReturnValue`: production forwards the single `substate.Output` through the tracer call and never assigns that receipt field. The same output is used for success and revert-failure forwarding; non-revert failure forwards an empty array. The generated finalization result is a combined observation containing the terminal trace and the separately classified `TransactionResult`; `status` remains the receipt status and is not used to infer the result. Logs, output, error text, state roots, hashes, addresses, effective prices, and exception identities are typed oracle payloads rather than cryptographic, VM, or enum implementation models. The normal-return and caller-route assumptions are typed adapter inputs; they do not prove the outer `TransactionProcessorAdapterExtensions.ProcessTransaction` handoff or any block-processor orchestration.

The three EIP diagnostic receipt properties are modeled as concrete natural-number fields with their production zero defaults. Their source guards determine when a nonzero value overwrites the default; no assignment-presence bit is claimed.

## Explicit exclusions and assumptions

The package excludes:

* parallel workers, BAL execution, and any shared-header parallel semantics;
* invalid snapshot values, unsynchronised receipt/gas histories, `SetReceipt` states, and other invalid state construction;
* receipt Bloom, RLP, trie, block/state-root correctness, and receipt/database persistence;
* VM execution, gas production, world-state effects, and DI/CLR behavior;
* nested tracer totality and allocation/performance claims.

The normal-prefix theorem assumes the snapshot is a valid retained prefix and the receipt and cumulative-block-gas histories are synchronised. `CurrentTx!` is represented by the supplied transaction input. No production bug is claimed or changed by this package.

`ProductionFinalizeDomain input` is the reachable-finalize adapter obligation: a successful terminal status implies `EvmExceptionType.None`. Failure with `EvmExceptionType.None` is intentionally admitted for ordinary revert/failure results, while failure with a non-None type is the exceptional result case. The model's `TransactionInput` derives `IsContractCreation` from `To`, and the refinement exposes the resulting `isContractCreation ↔ to = none` relation; proving that arbitrary production `Transaction` instances project into this structurally consistent model remains outside the package. The `vmError` oracle is total because it represents the source's total `FastToString()` fallback, and is ignored when the exception type is None. `ShouldRevert` remains an independent source-derived output guard because VM execution and the caller's upstream substate invariant are outside this package.

The exact-base/no-override condition is a caller construction assumption. Standard construction and DI/CLR dispatch are not extracted; subclass tracers such as Optimism's `BuildReceipt` override are outside the claim.

The consensus-side `TransactionProcessorAdapterExtensions.ProcessTransaction` wrapper and the later `BlockValidationTransactionsExecutor.ProcessTransactions` fold are outside this terminal slice. A future block-facing composition may use this transition only through an explicit typed normal-return adapter and the post-transaction `CommitState` boundary.

The delegated Lean closure is pinned transitively in schema-3 `SOURCE_PINS.json` and the schema-9 source manifest: the accounting generated/refinement files, `BlockReceiptGas`, `TransactionGas`, and the generated/refinement transaction-initialization files. Each of the six files has missing-file and byte-drift controls, and a test checks the inventory equals the complete local import closure. This prevents a changed imported specification from being silently accepted under an unchanged top-level proof file.
