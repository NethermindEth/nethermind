# KECCAK256 opcode extraction and refinement scope

This package admits a pinned standard-mainnet Amsterdam production slice for opcode `0x20`. It closes `IVirtualMachine` through `EthereumVirtualMachine`, the standard build selection, the complete named-fork ancestry, all four tracing/cancellation dispatch tables, `KeccakOpcode<TTracingInst>`, `InstructionKeccak256`, and the gas, memory, stack, and tracing members that determine its immediate observable transition.

Every selected syntax node is admitted by an exact case-sensitive tuple of source path, namespace, nested generic owner path, member kind, member name, generic arity, and parameter types. The manifest pins both every selected node and every complete source file, while `Directory.Build.targets` is pinned as a raw standard-versus-zkEVM build input. Missing, extra, duplicate, case-aliased, null, malformed, or changed serialized fields fail before Lean emission. All SHA-256 values must be exactly 64 lowercase hexadecimal characters.

The generated theorem-free Lean transition is emitted only from validated deserialized IR. It does not import or call `Eip803x.Evm.Keccak256`. It independently models instruction-trace start before PC advancement, one-byte PC and one-opcode-count advancement, atomic offset/length pop, checked ceiling word count, fixed-plus-word charge before the overflow flag, bounded logical memory expansion before its gas charge, retained stack/memory/gas mutations on each failure, exact zero-extended oracle input, replacement of two operands by the hash word, state-gas field preservation, traced stack push, and the immediate dispatch handler's successful instruction-trace end. Handler failures deliberately leave the immediate trace open because production closes them later in the outer VM error path.

`Refinement/Keccak256Opcode.lean` erases PC, opcode count, and trace observations and proves the generated Amsterdam transition equals the independently reviewed handwritten `Eip803x.Evm.Keccak256.execute` for every logical machine state, dispatch table, and hash oracle. Separate theorems pin all four closed roots and the trace-start/push/end primitives.

The hash function is an explicit oracle. No theorem covers the Keccak permutation, `ValueKeccak`, `KeccakCache` lookup or synchronization, cache-key hashing, cache correctness, `ValueHash256` byte layout, SIMD/native behavior, or CLR/JIT/AOT execution. The source admission proves only that the handler crosses that named boundary with the modeled memory slice. Unsafe stack storage, `UInt256` and hash representation, fresh-array runtime initialization, allocation/pooling/aliasing, tracer callback behavior or exceptions, cancellation polling, opcode-counter overflow, outer terminal-opcode and error trace closure, frame exceptional-halt settlement, rollback, transaction/block composition, database persistence, zkEVM sources, and hardware remain explicit obligations.
