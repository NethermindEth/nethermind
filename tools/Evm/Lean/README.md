# EIP-8037/8038 Lean reference

This began as the first formal-verification milestone for Nethermind's Amsterdam gas accounting. It provides an executable Lean model and machine-checked proofs for the common state-gas reservoir algebra and the complete EIP-8038 SSTORE pricing table. The end-state target now includes the complete standard mainnet EVM, outer transaction processor, and block processor; [VERIFICATION_SCOPE.md](VERIFICATION_SCOPE.md), [ARCHITECTURE.md](ARCHITECTURE.md), and [PRODUCTION_SURFACES.md](PRODUCTION_SURFACES.md) define that target and its fail-closed claim gates.

It does not yet prove the complete production refinement or cover whole account operations, CREATE, unrelated opcodes, precompiles, transaction processing, or block processing end to end. The repository currently contains several source-to-Lean connection slices, a reviewed handwritten account-pricing reference, a narrow production account-access pricing leaf, a narrow standard-mainnet system-transaction routing leaf, an accepted pre-commit nested-frame journal slice, accepted Stage A frame routing/dependency extraction, accepted bounded inline- and full-precompile refinements, and a handwritten Stage D single-iteration control-agreement check that is not a production refinement. Production delegates state-gas charging to a pure value kernel; `Refinement/StateGasCharge.lean` proves its generated definition refines `GasMachine.chargeState` under explicit representation, well-formedness, and no-overflow obligations. The remaining refund/refill/frame accounting roots are isolated in a second value kernel; `Refinement/StateGasTransition.lean` proves every generated root equivalent to a handwritten production-shaped specification under explicit machine-width/no-overflow predicates. Transaction gas initialization, scalar normal-settlement accounting, and the two-dimensional block-inclusion/execution-gas checks are separately extracted and related to handwritten formulas. Only selected roots are connected to independent semantics; whole account-operation pricing, production caller invariants, complete executable frame transitions, concrete frame baselines and adapters, end-to-end exceptional-halt settlement, fees, receipts, and processor composition remain open. The `evm formal charge-state` and `evm formal state-transition` commands expose the real production adapters through decimal-string NDJSON for byte-exact differential checks.

## Build and run

From this directory:

```powershell
lake build
lake exe eip803x-reference
./Verify.ps1
```

`Verify.ps1` is the fail-closed connection gate. It builds `Evm.slnx`, regenerates and byte-compares every selected kernel's Roslyn IR, source manifest, and generated Lean module, regenerates and byte-compares the opcode/precompile and transaction/block processing inventories, rejects Lean placeholders, builds all Lean proofs, runs focused production-kernel and block-processor tests, and byte-compares the Lean charge and 28 transition vectors with the real production adapters. It also hash-pins and structurally binds every BLS12_MAP_FP2_TO_G2 success/failure fixture record to its Lean transcription. A fresh complete serialized pass remains pending the transaction/block dependency cascade; earlier passing package and regression runs do not establish a green current aggregate. The recorded consolidated accepted-precompile regression selector through all 18 Amsterdam leaves passed 2,369 of 2,370 cases with the existing maximum-round BLAKE2F case intentionally skipped. The consolidated SELFDESTRUCT selector passed 102 of 102 cases, and the accepted pure-word selector passed 2,430 of 2,430. These production tests support the component results but do not replace extraction or refinement proofs.

`dotnet Evm.dll formal coverage --repo-root <repository>` produces the canonical machine-readable dispatch/precompile inventory. It enumerates every byte in the 256-entry standard dispatch table, evaluates source guards against `Amsterdam.Instance` at the synthetic mainnet activation, and cross-checks the registered standard precompiles. The command is deliberately an inventory/reachability gate: enabled entries are mapped to source dispatch handlers, but no opcode, precompile, frame, transaction, block, or cryptographic semantic proof is claimed. `Verify.ps1` fails if the checked-in JSON is missing, stale, or cannot be regenerated.

`dotnet Evm.dll formal processing-coverage --repo-root <repository>` produces the corresponding standard-mainnet transaction and block-processing reachability/order inventory. It anchors production DI, 45 transaction steps including CREATE destination classification/charge/collision-before-value-transfer, the 17 required synchronous phases from suggested-block checks and branch preparation through `CommitTree`, invalid-result classification, and head/processed-chain finalization, plus the registered parallel/BAL path. It also fails closed if the EIP-161 reaping anchor is missing, moved, or no longer precedes persistent-storage commit. It explicitly records parallel equivalence as unproved and supplies no transaction, block, root, or persistence semantics by itself.

The executable emits CSV with decimal integers only. Each row includes original/current/new storage values, warmth, and the computed execution charge/refund and state charge/refill, making it suitable as the Lean side of a later differential harness without JSON floating-point ambiguity.

`NormativeVector.all_pass` checks the entire cold/warm table during compilation for every schedule. The vector expectations are expressed independently in terms of schedule fields, so changing a fork constant requires editing only the concrete schedule instance; changing a pricing branch without updating its proof fails the Lean build.

Dirty slots are necessarily warm in reachable EVM executions. Their cold vectors are intentional cross-products that test `AccessStatus` independently; they are not claimed as reachable normative traces.
