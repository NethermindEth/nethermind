# Test plan

The C# mutation suite exercises the extractor, not production code.

- deterministic extraction yields byte-identical IR, manifest, and Lean artifacts;
- checked-in artifacts equal a fresh source extraction;
- the generated Lean file remains theorem-free and contains the finite-width transition plus emitted source-lowering metadata;
- every ordinary source mutation first fails the reviewed `Admission/ProductionClosure.txt` check before an output artifact can be written; the closure separately pins complete path/owner/signature-qualified method/property/enum tokens, so an unmodeled branch edit cannot be blessed by a regenerated source hash;
- source mutations to prefix order, ordinary/system routing, signed-`Int32` option backing, combined `||` short-circuiting, reset placement/argument, metrics equality, effective-price cap, sender recovery trace/create/throw ordering, premium calculation, transaction/type/blob-gas projection, standard blob-fee adapter registration and fee-per-blob failure zero output, checked-overflow routes, warmup minimum debit, and nonce increment fail extraction;
- test-only source mutations of a branch conjunct, an appended `UpdateMetrics` operation, stage ordinal, source member, numeric type, nullable adapter field, and formula fail the supported lowering even without the reviewed closure; the paired `UpdateMetrics` source lowering produces different live Lean metric-gate code in that test-only path, while the production admission path rejects the unreviewed source mutation;
- source/IR mutations of branch guards, terminals, grammar identity/category tags, source owners (including coordinated owner-plus-description edits), widths, operation ordinals, adapter premise bindings and projection trees, effects, and IR/manifest bytes (including null structural values) are rejected by the emitter before output; the dedicated `sourceGrammarSemantics` premise is also required and cannot be replaced with a source-bound adapter;
- the IR has the seven ordered stages and nineteen ordered branch identifiers.

Lean vectors cover a static failure, the explicit static-success adapter boundary at a 21,000 gas limit, signed-option boundary exclusion, EIP-2780 pre-intrinsic sender coherence, nullable blob-fee-cap exclusion and its opaque terminal at the `BuyGas` dereference point (after preceding state effects), recovery throws retaining changed-sender/debug/warn and trace effects, standard-world successful creation resetting deliberately nonzero effective balance/nonce, an alternate-world vector proving creation is not universally forced to zero, a typed `CreateAccount` adapter throw, an absent changed recovered sender reaching the typed `SetNonce` throw, recovery-create followed by sender rejection and restore request, premium rejection, checked `UInt256` overflow with retained low out values, warmup partial debit, both blob-calculator false outputs, source-derived blob-gas width wrapping, normal debit/nonce continuation, and `ulong.MaxValue` wrapping when validation is skipped. The 21,000-gas vector checks only the model's named adapter premise; it is not an integration execution against Nethermind.

Mutation tests prove the source binder fails closed for the listed source-shape changes. The refinement theorem is the formal evidence for equality of the generated and handwritten finite-width models across the explicit generated-to-reference observation map, conditional on `sourceGrammarSemanticsCoherent`. That premise is a blocking external compiler-resolution audit obligation, not evidence that this syntax-only extractor has proven C# semantics. Test vectors are execution checks, not a replacement for that theorem.
