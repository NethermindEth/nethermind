# Scope and non-claim

## Included transition

The executable model starts at the admitted six-parameter `Execute` under a successful-`ValidateStatic` adapter premise. The source closure separately proves the accepted call path is `Process → ExecuteCore → Execute(tx,tracer,opts) → RecoverSenderBeforeIntrinsicGas → CalculateIntrinsicGas → Execute(..., intrinsicGas)`, including the EIP-2780 sender mutation before intrinsic gas. It preserves the exact modeled sequence through `IncrementNonce`, including the three-term left-to-right rejection gate and its one outer restore block. `ValidateStatic` itself is not verified: the bounded transcription corollary assumes static success, a non-null post-static sender, and a gas limit of at least 21,000. That is a named adapter premise, not a claim that this package has produced a real production execution witness. The corollary also requires `sourceGrammarSemanticsCoherent`: an external error-free compiler-resolution audit must show that the finite grammar-assigned source identity/category tags agree with the reviewed source closure. This package does not perform that audit or claim production C# semantic refinement. It further requires a non-free, non-system transaction, a coherent byte-backed `TxType` projection, nullable blob-field coherence, standard-world-state creation behavior, source-width values, a nonnegative signed-`Int32` option value (`raw < 2^31`), and options not exactly equal to `SkipValidation` or `BuildUp`: the former routes through `SystemTransactionProcessor`, while exact `BuildUp` takes a pre-prefix `WorldState.TakeSnapshot` action not represented by this post-static-prefix observation.

Included state observations are:

- `Transaction.SenderAddress` recovery, the resulting delete-caller decision, and terminal recovery state;
- separate supplied-sender, post-EIP-2780, and changed-recovered-sender existence facts; standard `WorldState → StateProvider` creation of an effective zero account; effective-sender balance debit; and either an effective-sender nonce update or the source's terminal absent-account `SetNonce` throw;
- `UpdateBlockGasPrice` call delta at its exact `None`/`Commit` equality gate;
- `TraceLogInvalidTx` call delta, including `SENDER_ACCOUNT_DOES_NOT_EXIST`, and conditional recovery logger events;
- effective/opcode price, premium, reserved payment, and blob base fee, including a wrapped `UInt256` out value on a terminal checked-arithmetic failure;
- `Return`, `Throw`, and `Continue` terminal forms;
- the `Restore` request with `resetBlockChanges: false` after only the combined sender/gas/nonce failure gate.

## Excluded transition

The package stops before `PrepareSimpleTransferFastPath`. It does not model fast path selection, cached code/delegation lookup, precommit, available-gas initialization, execution, frame behavior, settlement, receipts, block processing, or state-root persistence.

It also excludes static-admission internals; signature recovery, account reads, contract-sender classification, tracing/log persistence, and lower-level blob fee calculation are typed input observations. `CreateAccount` is modeled as zeroing fields only under the explicit standard-mainnet `IWorldState → WorldState → StateProvider` adapter predicate; alternate world-state modes are not assigned that behavior. A failing create adapter observation becomes a typed `createAccount` throw before fields change. A changed recovered sender whose observed account is absent reaches the explicitly modeled `SetNonce` throw before any nonce write, mirroring the admitted `StateProvider.SetNonce` null-account behavior. Adapter journals and exception mechanics remain excluded. The ordinary route source-binds processor, blob-fee, and world-state registrations, and explicitly rejects reliance on system, XDC, Taiko, or alternate processor routes. No compiler-resolution, C# semantic, CLR, JIT, DI-resolution, plugin, database, concurrency, or cryptographic correctness claim follows from this package.

## Representation contract

`Nat` is only the carrier for a source-width value. `u64` and `u256` make the width explicit at the model boundary. Each checked `UInt256` calculation carries a modulo-`2^256` out value plus an overflow Boolean, matching the admitted `out`-parameter observation even on failure; `ulong` increment follows its source branch and wraps modulo `2^64`. The arithmetic behavior is an explicit adapter premise for the pinned `Nethermind.Numerics.Int256` 1.8.0 dependency, not a proof of that package binary.

`preIntrinsicSender` records the caller state before EIP-2780's `RecoverSenderBeforeIntrinsicGas`; `tx.sender` and `suppliedSenderAccountExists` are jointly constrained to the post-EIP-2780 sender and account-existence observation consumed by the six-parameter `Execute`. The later `RecoverSenderIfNeeded` test first observes that supplied sender. If it retains that sender, the effective account fact must equal the supplied account fact. If it changes to a recovered sender, the effective account fact must equal `recoveredSenderAccountExists`; a missing changed recovered account is retained as the explicit pre-`SetNonce` throw path. The effective-sender fields are the later `ValidateSender`, `BuyGas`, and `IncrementNonce` observations. `MaxFeePerBlobGas` and `BlobVersionedHashes` are nullable input fields, with outer-null hashes contributing zero to the source-bound `GetBlobCount`, then source `int → ulong` cast and unchecked `ulong` `blobCount * GasPerBlob` multiplication. The production predicate excludes a blob transaction with an absent fee cap. The internal malformed-cap terminal occurs only where source dereferences that cap in `BuyGas`, so it retains prior price, metrics, recovery, sender-validation, and fee-check effects without inventing a combined-gate reset. The predicate also requires zero facts whenever the effective sender is absent, standard-world-state creation, source-width values, and an option raw value representable by the default signed-`Int32` enum backing. Static-failure and malformed cases remain only in the internal executable model.

`WorldState.Reset` itself is not reimplemented. The output records that source would call it, preserving the pre-reset partial effects so an adapter proof can connect the journal implementation later. Metrics and log fields likewise record calls, not mutable external backend state.

Regeneration compares those reviewed identities before writing IR, manifest, or Lean, rather than treating a freshly computed manifest hash as approval. The IR repeats the closure identity and makes source-width rules, formula operations, branch guards and terminals, visible effects, route edges, and external adapter premises explicit. The emitter turns the admitted formula/guard grammar into live Lean transition code and the adapter-premise list into the bounded-transcription coherence conjunction; every unsupported or incomplete field is rejected. `SourceExpression` identity/category tags are finite grammar assignments, not `ISymbol`/`ITypeSymbol` results. `sourceGrammarSemanticsCoherent` therefore remains a blocking external compiler-resolution audit obligation in the manifest and theorem domain. This is a fail-closed manually specified AST lowering grammar, not an automatic proof that arbitrary C# executes as Lean.

The generated Lean computes the normalized UInt64 blob gas from those source-bound projections; it is no longer a free adapter field. This does not extend the claim to transaction construction, type dispatch beyond the ordinary route, blob-list traversal, or the blob-fee exponential implementation.
