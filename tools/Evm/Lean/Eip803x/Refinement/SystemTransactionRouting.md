# Candidate standard mainnet system-transaction routing refinement

This unaccepted candidate slice records Nethermind commit `b2478235e71e6a7ec2a509aa0155e25d5fdfff80` as its ancestor baseline. That commit establishes source lineage; it does not contain the subsequently added routing kernel. The authoritative production identity is the exact set of current source-file SHA-256 hashes in `SystemTransactionRoutingKernel.source-manifest.json`. Pending independent rereview, the candidate proves a deliberately narrow claim about the standard mainnet transaction-processor route:

- `TransactionProcessorBase<TGasPolicy>.ExecuteCore` selects the system processor for a transaction classified by `TransactionExtensions.IsSystem`, or for the exact `ExecutionOptions.SkipValidation` value.
- `SystemTransactionProcessor<TGasPolicy>.Execute` assigns the pinned pay-original-value decision to the exact `_payOriginalValue` field, its exact `PayValue` override reads that field, both inherited execution paths virtually dispatch to the override, and effective options containing `SkipValidation` reach the inherited execution path. Before each semantically bound routing-kernel/classifier, normal/system dispatch, or base/virtual `PayValue` call, no ordinary by-value call that can execute before that target in the caller CFG may receive the modeled `Transaction` or `IReleaseSpec` reference (directly or through an alias).
- The extracted claim is limited to the named normal sequential block-counter Boolean gate in `UpdateHeaderGasUsedAndPayFees`; effects of its virtual `PayFees` callee, including any header or receipt mutation, remain outside this claim.
- The standard `BlockProcessingModule` registration calls the exact production `AddScoped<ITransactionProcessor, EthereumTransactionProcessor>` extension, which delegates the same two types to the exact `BindScoped` implementation and its pinned Autofac scoped externally-owned registration chain. The sealed processor inherits the default virtual factory that constructs `SystemTransactionProcessor<TGasPolicy>`.

The production change is an allocation-free static kernel of Boolean and flag operations. Existing production methods delegate only those decisions to it. The generated Lean module contains definitions only. `SystemTransactionRouting.lean` independently defines the handwritten route/option/counter model and proves the extracted definitions extensionally equal to it. The vector module covers exact-skip versus combined flags, warmup, classified system transactions, effective options, normal-counter exclusion, and six deliberately broken alternatives.

## Source admission

The dedicated Roslyn extractor admits exactly these seven source files:

1. `SystemTransactionRoutingKernel.cs`
2. `ExecutionOptions.cs`
3. `TransactionProcessor.cs`
4. `SystemTransactionProcessor.cs`
5. `TransactionExtensions.cs`
6. `BlockProcessingModule.cs`
7. `Nethermind.Core/ContainerBuilderExtensions.cs`

It records the authoritative SHA-256 identity of every admitted current source and the ancestor baseline separately in the source manifest. Admission rejects preprocessor directives, disabled text, partial types, extern or qualified aliases, file-level aliases, namespace-level aliases, global imports, static imports, selected-symbol shadow declarations, and a competing `AddScoped` declaration in the mainnet module source. It checks the exact closed kernel, enum values, call ordering, override surfaces, assigned decision field, cached default factory, system route, classifier, the production `ContainerBuilderExtensions.AddScoped<T, TImpl>` and `BindScoped<TTo, TFrom>` bodies, and the complete `Load` control-flow graph: the admitted registration must be reachable, must dominate every reachable method exit, and must be the only semantically bound processor registration. Every builder use in `Load` must remain a complete direct chain of admitted source/ordered extensions; builder aliases, deferred captures, local functions, unknown operations, preceding exits, and later processor registrations are rejected. Every direct-argument check explicitly selects one of two policies. The routing-kernel/classifier, normal/system dispatch, and three base/virtual `PayValue` bridges build a caller CFG and reject an ordinary by-value `Transaction` or `IReleaseSpec` handoff through a direct, conditional, `ref readonly`, or ordinary alias when it can execute before the bound target, including later-textual calls reachable through a loop or `goto`; target-call arguments are excluded. They also reject an unmodeled instance or reduced-extension receiver and a captured method group over those references; the exact source-bound `TransactionExtensions.IsSystem` classifier is the sole permitted receiver call before the normal and system dispatches. Parenthesized, implicit/explicit/`as` conversion, null-suppressed, conditional, and coalescing forms are resolved fail closed. A later straight-line operation in the target's own basic block is not treated as preceding unless a non-empty CFG cycle returns to that target. The option-forwarding, EVM-call preparation, system-option, base-execution, and counter checks apply the same CFG-before-target preservation filter to parameter writes, aliases (including `ref readonly`), and `ref`/`out`/`in` uses, but explicitly model only their `opts` (and counter `_parallel`) inputs. Their `tx`/`spec` checks bind call arguments, not heap state: current production intentionally performs recovery, preparation, and execution work before those downstream calls, and no such object state enters the extracted Lean formula. `ExecutionOptions` is an enum value, so an ordinary by-value call cannot mutate its caller's value. The same `opts` parameter is forwarded through both the EVM and simple-transfer paths into the Boolean counter gate.

## Boundary

This is not a proof of transaction execution, VM behavior, world-state reads or writes, tracing, address identity, CLR/JIT execution, Autofac itself, or the correctness of the Roslyn compiler/extractor. The Lean route accepts the result of the pinned production classifier as a Boolean; the meaning of `SystemTransaction`, `Address.SystemUser`, and the Optimism system flag is source-pinned but not modeled as object or address semantics. Its option structure represents exactly the five declared independent flags and excludes unnamed underlying-enum bits. The by-value-reference barrier applies only to the four route/classifier/dispatch bridges and three payment bridges; it is not a proof of a bound endpoint or any transitive object/world-state effect. The explicitly direct-binding-only option, preparation, base-execution, and counter corridors do not claim unchanged `Transaction` or `IReleaseSpec` heap state. The theorem proves only the extracted Boolean decision for zero participation in the named normal block-counter gate, not that no unrelated code or unanalyzed virtual/transitive call can mutate a header or receipt. It also does not prove AuRa or other engine overrides: the standard mainnet concrete route is admitted precisely because its sealed processor inherits the default virtual factory. Finally, adding validation-skipping effective options is not a claim about the state, gas, refund, or trace result returned by `base.Execute`.

Consequently this slice contributes one checked production-refinement edge to the larger verification program; it does not justify saying that the entire EVM, transaction processor, block processor, or Nethermind has been formally verified.
