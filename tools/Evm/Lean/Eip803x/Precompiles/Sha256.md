# SHA-256 precompile leaf reference

`Sha256.lean` is a narrow handwritten, executable reference for the pinned
standard-mainnet SHA-256 precompile at address `0x02`.  It models the leaf
metadata and pricing, and an unconditional successful operation whose result is
an explicit 32-byte SHA-256 oracle digest:

- address `2`, name `SHA256`, and caching enabled through the `IPrecompile`
  default;
- configurable `Schedule.base` and `Schedule.word` prices;
- `base + word * ((input.length + 31) / 32)` gas;
- success `true`, exact oracle bytes, and exactly 32 output bytes.

The Amsterdam instance is `{ base := 60, word := 12 }`.  These constants and
the ceiling formula were checked against the pinned executable Ethereum
specification at
[`ethereum/execution-specs@0cc100eb.../amsterdam/vm/precompiled_contracts/sha256.py`](https://github.com/ethereum/execution-specs/blob/0cc100eb190b64b23baba72dac0165652eaec252/src/ethereum/forks/amsterdam/vm/precompiled_contracts/sha256.py)
and its gas table
[`amsterdam/vm/gas.py`](https://github.com/ethereum/execution-specs/blob/0cc100eb190b64b23baba72dac0165652eaec252/src/ethereum/forks/amsterdam/vm/gas.py#L104-L105).
The EELS source charges `ceil32(len(data)) / 32` words and writes
`hashlib.sha256(data).digest()` after charging.  The exact Nethermind sources
used for the adapter comparison are
[`Sha256Precompile.cs`](../../../../../src/Nethermind/Nethermind.Evm.Precompiles/Sha256Precompile.cs)
and
[`std/Sha256Precompile.cs`](../../../../../src/Nethermind/Nethermind.Evm.Precompiles/std/Sha256Precompile.cs).
The production test fixture is
[`Sha256PrecompileTests.cs`](../../../../../src/Nethermind/Nethermind.Evm.Test/Sha256PrecompileTests.cs).

## Proof and vector surface

`Sha256.lean` contains 15 named theorems.  They prove the two ceiling
boundaries, schedule-polymorphic exact pricing at and just past a word
boundary, empty-input pricing, length-only pricing dependence, exact metadata,
and the oracle/success/output contract.  All gas fields are `Nat`, and no
axioms, `sorry`, or placeholders are used.

`Sha256Vectors.lean` contains six independently authored boundary vectors for
input lengths `0`, `1`, `31`, `32`, `33`, and `100`.  The expected gas values
are `60`, `72`, `72`, `72`, `84`, and `108`.  Expected digest literals and the
finite oracle's digest literals are separate tables, so changing either side
breaks the checked vector theorem; every literal carries an explicit 32-byte
proof, so malformed literals fail compilation.  The oracle fixture is
intentionally not a SHA-256 implementation.  The file has three named vector
theorems, 25 executable examples, and nine mutation sentinels for
floor/ceiling, base price, word price, address, name, caching, one digest byte,
output length, and success.

Reproduce the targeted build from this directory:

```powershell
$env:ELAN_HOME = 'D:\tmp\formal-lean-toolchain\home'
& "$env:ELAN_HOME\bin\lake.exe" build `
  Eip803x.Precompiles.Sha256 `
  Eip803x.Precompiles.Sha256Vectors
```

## Trust boundaries and limitations

This is a pure leaf reference, not a production refinement and not a whole-EVM
claim.  In particular it does not prove:

- that Nethermind's dispatch table or provider registration reaches address 2;
- wrapper gas debit, frame behavior, account touch, rollback, returndata
  copying, or cache-key behavior;
- `Metrics.Sha256Precompile++`, allocation success, array ownership, pooling,
  or CLR/JIT/AOT semantics;
- `ReadOnlyMemory<byte>`/`Span<byte>` conversion, `SHA256.TryHashData`, its
  `bytesWritten` result, native crypto provider behavior, or hash correctness;
- equality between the explicit oracle and the platform SHA-256 primitive.

The 32-byte `Digest` type makes the output-size precondition explicit and
proves the leaf contract without silently assuming cryptographic correctness.
The literal boundary oracle is only a known-answer test fixture; replacing it
with the real cryptographic primitive is a separately named adapter obligation.
