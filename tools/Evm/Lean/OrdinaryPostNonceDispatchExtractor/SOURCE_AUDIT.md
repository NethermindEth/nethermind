# Source audit

The package admits only the files listed in `Admission/ProductionClosure.txt`.
Each file is read as strict UTF-8 and parsed with the repository's C# 14
Roslyn parser. The extractor rejects source-file identity drift before writing
checked-in artifacts.

The semantic pass constructs a Roslyn compilation over the admitted trees and
records, for every lowered node, its containing member, canonical syntax,
token/syntax fingerprints, resolved `IOperation` kind/type/implicitness,
data-flow success and read/write sets, semantic target symbol, receiver type,
source position, statement ordinal, and containing CFG block. It requires the exact
six-parameter overload and exact helper/invocation argument shapes, then checks
the CFG reachability/order and dominance from the bound `IncrementNonce` call
through both handoff branches.

The compiler is intentionally an admitted-source semantic aid. The
transaction-processor semantic unit contains the processor and the exact
source support files listed in the closure (the interface, system processor,
standard dispatch flags, metrics, substate, settlement, and virtual-machine
interface); the code-repository semantic unit also compiles the actual
production `Metrics.cs` and `Metrics.std.cs` files alongside both code
repositories. The CodeInfo semantic unit includes its exact jump-destination
analyzers. The two admitted `Transaction` partials form a separate source
unit, and the remaining route/policy units are compiled independently. All
units use the deterministic release assembly closure rooted at
`src/Nethermind/artifacts/bin/Nethermind.Init/release`, with the source
project's assembly identity used for the production friend-access surface.
`VirtualMachine.cs` is parsed to verify the exact
`VirtualMachineStatics.RestoreRipemdTouch` source declaration. The processor
semantic model binds each of its two calls to the checked-in
`Admission/VirtualMachineStaticsAdapter.cs` compiler-only empty-body
declaration. Independently, the exact `Nethermind.Evm` metadata reference is
inspected for one actual `VirtualMachineStatics.RestoreRipemdTouch` symbol and
validated for return type, static/accessibility modifiers, parameter
names/types/ref-kinds, target assembly, and metadata location. The adapter
path and SHA-256 are recorded in the generated IR. The out-of-scope VM body is
therefore a declared, fail-closed adapter boundary rather than an undeclared
synthetic signature. The production repository's full project compilation,
CLR dispatch, DI container, and runtime effect results are outside this
package.
Those boundaries are represented as typed adapter premises in the IR rather
than silently treated as theorems. The Lean emitter has a closed, typed lowering
vocabulary for the admitted option initializers, Boolean guards, commit/lookup
effects, and the `CalculateAvailableGas` result conditional; it does not
interpolate arbitrary C# text into executable Lean. The option expressions,
branch conditions, adapter domains/projections, and gas condition/result arms
are checked as complete source-expression trees against their bound source
nodes. The generated gas classifier consumes the observed condition result and
the member name carried by each bound arm; it is not an implementation of the
external gas policy. Canonical source forms outside that vocabulary are rejected
before emission.
All resulting compilation error diagnostics are rejected. Every source binding
also records its target symbol kind and candidate state; unresolved, error-type,
candidate, or ambiguous bindings are rejected before an IR is written. This
source-closure check does not claim that the entire repository compilation or
the CLR/JIT has been reproduced.
The generated `Options.raw : Nat` is an explicit nonnegative projection of the
source's signed-`Int32` `ExecutionOptions`; its fixed-width representation and
bit arithmetic are not claimed by the refinement. The model's `Nat`/`Int`
transaction and gas fields are likewise unbounded projections of the source
fixed-width values, so range and conversion obligations remain external.

The ordinary-stateful prefix is recorded as a dependency identity and an
explicit boundary note. No generated bytes from it are parsed to determine the
post-nonce formulas. The generated lifecycle artifact is similarly an erasure
vocabulary dependency only.
