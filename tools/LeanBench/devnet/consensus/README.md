This creates a fresh Kurtosis `lean8288` network: two execution nodes, two Lighthouse beacon nodes, 32 validators and Dora. It uses Amsterdam/Gloas at genesis, activates the EIP-8288 prototype, and leaves Bogota/Heze disabled. The funded test sender is private key 2 on chain ID 10088288.

The devnet Engine relay shares a bounded proof cache between both beacon nodes. It preserves `recursiveStarkProof` and `recursiveStarkBlockDepsHash` across Lighthouse's payload encoding, keyed by the real block hash. It forwards every Engine verdict unchanged and rejects a proof cache miss. This is a local interoperability bridge, not CL support for the prototype's additional consensus fields or proof-bearing inclusion lists. Cache files persist within the relay container; recreating the enclave creates a fresh chain.

Prepare an isolated checkout of `ethpandaops/ethereum-package`, pin its revision, copy `../engine_proxy.py` to `ethereum-package/lean-engine-proxy.py`, and run:

```sh
python3 patch_package.py ethereum-package
cp -a /path/to/published/client ./client
docker build -f Runner.Dockerfile -t nethermind:lean8288-devnet .
docker build -f Genesis.Dockerfile -t ethpandaops/ethereum-genesis-generator:lean8288 .
kurtosis run --dry-run --enclave lean8288 --args-file params.yaml ethereum-package
kurtosis run --enclave lean8288 --args-file params.yaml --parallelism 1 ethereum-package
```

`Runner.Dockerfile` uses the host's cached .NET 10 Nethermind base image and replaces its client with the published build, including the native Lean library. The genesis wrapper uses the official generator's EL stage, adds prototype activation and the funded account, then generates a matching beacon genesis. JWT and validator secrets are generated by Kurtosis and remain in enclave artifacts.

The package patch routes both CL Engine connections through one authenticated relay and allocates these distinct host ports:

| Service | Node 1 | Node 2 |
|---|---:|---:|
| Execution JSON-RPC | 19445 | 19545 |
| Execution Engine | 19551 | 19651 |
| Execution P2P | 19403 | 19503 |
| Beacon REST API | 19552 | 19652 |

Dora listens on port 19490. Check real beacon progress at `/eth/v1/beacon/headers/head` and `/eth/v1/beacon/states/head/finality_checkpoints`; the existing Engine-driver dashboard on 19480 represents a separate network.

The configuration caps execution nodes at two CPU cores and 2 GB each, beacon nodes at one core and 1.5 GB each, and validator clients at half a core and 768 MB each. Run small proof-bearing transaction cases first. Do not submit large generic-proof batches merely to fill the network.
