Cache experiments, 2026-10-09

Baseline: 487bddc799823fb998f1793fe4717cf73faea109
Locks and AssociativeCache are unchanged.

Reproduce from the repository root:
  python tools/CacheExperiments/prepare.py
  dotnet build tools/CacheExperiments/CacheExperiments.csproj -c Release
  dotnet run --project tools/CacheExperiments -c Release --no-build -- validate
  dotnet run --project tools/CacheExperiments -c Release --no-build -- bdn
  dotnet run --project tools/CacheExperiments -c Release --no-build -- results.csv

The runs below used DOTNET_TieredCompilation=0. Set that environment variable
before running to reproduce the fully optimized JIT comparison. The default
runtime's tiering/PGO should also be checked before deployment.

BenchmarkDotNet 0.15.8, .NET 10.0.12 / SDK 10.0.401.
Single-threaded int keys and int values, existing McsLock in every LRU variant.
In-process non-emitting toolchain, 3 warmup and 7 measurement iterations,
100 ms target per iteration. Allocation excludes construction and warmup.
36 BDN cases on each of Windows x64 (Ryzen 9950X) and macOS ARM64 (Apple M4).
ARM64 used the same portable managed assemblies in an isolated worktree;
the remote checkout's source was not used to build the caches.

ARM64, capacity 16,384, mean nanoseconds per operation:
                         Original     MRU fast path     Slots + clear optimization
  Repeated MRU hit         23.75         18.43              19.75
  Random resident hit      24.41         23.50              22.67
  Existing-key update      25.84         25.02              23.42
  Insert with eviction     41.28         41.81              37.62
  Delete and refill        88.11         87.55              57.47
  Clear and refill/entry   33.52         32.55              24.57

Delete/refill: original 40 B/op; slots 0 B/op.
Clear/refill: original approximately 44 B/entry; slots 0 B/entry.
Ordinary hits, updates, and replacement at capacity already allocated nothing
in the original LRU. Subclasses retain their eviction snapshots/callbacks.
Slots retain their high-water capacity after Clear, but clear stored references.

Windows BDN showed the same allocation savings and an MRU-hit improvement;
several timing cases had substantial variance. Prefer the ARM64 numbers above
for interpreting this experiment, not claims about production throughput.
LruKeyCache uses the same slots and passed the reference model and its existing
tests; the BDN table specifically measures the key/value LruCache.

CLOCK experiment (benchmark-only; production CLOCK was not changed):
  - Original unlimited scan
  - Fixed budget 32
  - clamp(capacity / 64, 8, 256)
  - That budget rounded upward until coprime with capacity
  - That budget rounded upward to a prime coprime with capacity
  - Effective budget capped at capacity; exhausted scans evict the last inspected
    entry and advance the hand past it.

320 replay cases per architecture: capacities 32, 1009, 1024, 16384; repeated and
uniform hits, updates, insert/evict, delete/refill, clear/refill, hot set plus scans,
near-capacity working set, phase shifts, and a moving-window sweep diagnostic.
The replay is a simple Stopwatch harness, not BDN. It reports medians of seven
samples, with payloads/traces prebuilt; no end-to-end miss cost is modeled.

Example hit percentages, capacity 1009:
                           Original   Fixed32   Size15   Coprime15   Prime17
  Near-capacity workload    82.236     82.236    82.208    82.208     82.221
  Phase shifts              87.685     87.651    87.623    87.623     87.625
  Moving-window diagnostic  99.901     93.080    91.186    91.186     91.347

The diagnostic deliberately does not reload misses and is not a production hit
rate forecast. Short budgets bound work but change eviction quality. These traces
do not establish a prime-specific advantage; at power-of-two capacities the
chosen coprime/prime budgets often coincide. No production scan cap was selected.
CLOCK still allocated 40 B per successful update/insert for int/int in these tests.
Replacing its concurrent dictionary storage was not implemented: reusable slots
need a separately validated concurrent-publication design for arbitrary values.

Validation:
  108 Core caching tests passed, including a deterministic reference LRU model
  for both LRU variants and reentrant Clear callbacks.
  30 experimental CLOCK cases passed, checking exhausted-budget victims and
  concurrent set/get/delete/clear with key/value consistency and bounded count.
  Analyzer builds of Core, Core.Test, and the experiment project completed with
  EnforceCodeStyleInBuild=true and GenerateDocumentationFile=true: no IDE0005.
  Existing XML documentation warnings required TreatWarningsAsErrors=false and
  NoWarn=CS1591 for these analyzer runs; ordinary Release builds passed normally.
