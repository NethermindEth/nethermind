# Nethermind.Paprika

A vendored copy of the store layer of [Paprika](https://github.com/NethermindEth/Paprika), used by the
`PaprikaFlat` flat DB layout (`Nethermind.State.Flat/Persistence/PaprikaFlat`).

- Upstream: `https://github.com/NethermindEth/Paprika`, commit `9307ae3d4d2845e55dfe68e35519b99ce0057748`
  (main, "Different encoding for length and oddity (#484)").
- License: LGPL-3.0, as upstream.
- Namespaces stay `Paprika.*` so the files remain diffable with upstream. Whitespace was normalised once with
  `dotnet format whitespace src/Nethermind/Nethermind.Paprika --folder`; compare with upstream using `git diff -w`.

## Vendored files

Only the store layer, taken from `src/Paprika` at the commit above:

- `IBatch.cs`, `IReadOnlyBatch.cs`, `IDb.cs`, `NoopDisposable.cs`
- `Store/` except `StatisticsVisitor.cs` and `BatchMetrics.cs` (`RangeIterator.cs` is local, V18), and
  `Store/PageManagers/` (where `NativeMethods.cs` is local, V16, and `IPageAccessObserver.cs`, V17)
- `Data/`: `DataType`, `Key`, `NibblePath`, `NibbleSelector`, `SlottedArray`, `BitVector`
- `Crypto/`: `Keccak`, `KeccakHash`, `SpanExtensions`
- `Utils/SpanExtensions.cs`
- `Chain/BufferPool.cs`
- `Merkle/Key.cs` (despite its folder it declares `Paprika.Data` and holds `Key.Merkle`)

Excluded:

- `Account.cs`, `Data/Serializer.cs`: Paprika's account codec, which needs Int256. The flat layout stores Nethermind's
  Slim RLP instead.
- `Chain/` (except `BufferPool`), `Merkle/` (except `Key.cs`), `RLP/`, `IProvideDescription.cs`, `Data/BitMapFilter`,
  `Data/UShortSlottedArray`, `Data/PageExtensions`: the blockchain and Merkle layers. Trie nodes stay in RocksDB.
- `Utils/` except `SpanExtensions`: chain and Merkle helpers. `Utils/Metrics.cs` also needs HdrHistogram, and a
  `Metrics` type in a `Nethermind*` assembly would be picked up by Nethermind's `TypeDiscovery`.
- `Store/StatisticsVisitor.cs`: a diagnostic that needs HdrHistogram.
- `Utils/MetricsExtensions.cs`, `Store/BatchMetrics.cs`: vendored at first, then deleted with the meters they served
  (V13).
- `Globals.cs`: its only content is an `InternalsVisibleTo` for upstream's test assembly.

## Build deviations

- `LangVersion` 13, as upstream builds it (C# 14 changes span overload resolution).
- Analyzers and code style do not run (`RunAnalyzersDuringBuild=false`, `.editorconfig`), so the code stays as upstream.
- `NoWarn` adds `CS8604`, raised by upstream code.
- Native calls use `DllImport`, so nothing depends on source generators, which do not run with analyzers off.
- The assembly is `Nethermind.Paprika`; the root namespace stays `Paprika`.

## Known upstream issues left unpatched

These are on paths the flat layout never takes:

- `PagedDb.SetNewRoot` writes the next root slot outside `_batchLock`, so history lookups by hash can observe a root
  whose commit failed. The flat layout only opens the latest root.
- `DataPage.TryTurnToFanOut` assumes the page level parity equals the key oddity. Fixed-length keys never end at that
  depth.
- A write batch's `IdCache` grows without bound during the batch.
- `StateRootPage.DeleteByPrefix` with a prefix shorter than two nibbles clears only the buckets, not the keys shorter
  than two nibbles in the page's own map (`DeleteByPrefixTests.State_prefix_shorter_than_two_nibbles_deletes_keys_in_the_state_root_page`,
  ignored). The flat layout's only such key is its metadata, which it never deletes by prefix.

Two more waste pages without affecting correctness: `BottomPage.DeleteByPrefix` with an empty prefix registers its
children for reuse only after the reuse floor, even those written in the same batch, and `StateRootPage.DeleteByPrefix`
with a prefix shorter than two nibbles copies and empties the data page of every bucket it covers instead of dropping it.

## Re-syncing from upstream

1. `git -C <Paprika checkout> archive <commit> src/Paprika | tar -x -C <scratch>`.
2. Diff the vendored files against the new upstream files with `git diff --no-index -w`.
3. Re-apply the local modifications above, then run `dotnet format whitespace src/Nethermind/Nethermind.Paprika --folder`.
4. Run `Nethermind.Paprika.Test`.
