# Streaming conformance vectors

The `rollup0-conditional` JSON files are unchanged portable vectors from upstream Rollup0 #234 at the revision and checksums in its `provenance.json`. The top-level files test the authenticated, proofless-calldata profile. Its existing missing-proof-slot case expects `INVALID_ARGUMENT`, and three retained-window quota cases expect `RESOURCE_EXHAUSTED`; these four existing profile-specific expectations and the upstream file hash are recorded in the top-level `provenance.json`. The source project licenses them under MIT OR Apache-2.0. They use a public isolated test signer and the captured six-block window79..84.

StreamingConformanceTests sends the recorded protobuf payloads through the actual Nethermind mTLS endpoint, execution backend, settlement verifier and signer. The conditional replay preserves upstream requests, expected responses, cursors, public-input hashes and signer identities. The authenticated replay clears incoming proof bytes and retains its proof-count assertion and three aggregate-quota assertions. Only server-issued session IDs/epochs, diagnostic rejection text and cache-reuse reporting are normalized. Signatures are checked by recovery over the expected digest.

The production endpoint retains canonical L1/L2 parent authorization. Positive cases use predeclared fixture registration at recorded parent78,79,80 or83. Registration never follows an incoming request. Companion negative cases keep registration at parent78 and reject the unsettled subrange without signing. These tests establish wire compatibility under fixture authorization, not live conditional-profile equivalence or live external-composer interoperability.

CI resolves current public main and its matching Core gitlink once per job. It downloads current vector data automatically. Missing upstream vectors fail CI. No contributed Rust code is executed. Local tests can use this committed snapshot; runtime verification runs in CI.
