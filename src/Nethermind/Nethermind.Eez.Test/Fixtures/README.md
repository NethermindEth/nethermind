# EEZ stateless fixtures

Historical block, execution-witness and chain-configuration recordings originate from
`eez-association/eez-rollup0` at `9b9491c45875fdaf45d06ad0f092691a49a85936`
(`crates/eez-prover-stateless/tests/fixtures`), licensed `MIT OR Apache-2.0`.

| Directory | Content | Expected values |
| --- | --- | --- |
| `stateless-block-13` | empty block 13, chain id 1 | hash, post-state root |
| `stateless-checkpoint-2175` | block 2175, three transactions, chain id 1 | per-transaction state roots, block hash |
| `nonzero-outbound-630` | window 626..630, chain id 1 | final post-state root |
| `captured-devnet-window-84` | window 79..84, EEZ genesis chain id 6290 | window pre and post block hashes |
| `captured-devnet-window-468` | window 463..468 whose settling block carries outbound calls and an inbound delivery, chain id 6290 | block hashes, the attested public inputs hash, the mined proof |
| `captured-devnet-anchor-402` | window 397..402 settled by an anchor-only postBatch, ordinary L2 transactions, chain id 6290 | window pre and post block hashes, the attested public inputs hash |

The chain id 1 recordings predate the native system transaction type: their system calls are ordinary signed
transactions.

`settlement` holds the rolling-hash and public-inputs-hash vectors from `crates/eez-protocol/tests/fixtures` at the
same commit, generated by the protocol's Solidity oracles (`RollingHashVectors.t.sol`,
`PublicInputsHashVectors.t.sol`).

`captured-devnet-window-468` and `captured-devnet-anchor-402` were recorded on 2026-10-13 from an
isolated Kurtosis devnet of `eez-association/eez-rollup0` at
`fede75fc185f11a0b330de999dbffeae6d49d777`, with core protocol
`855fe0602484750861b4c31502a1a91355d33ed6`. The runtime binaries came from the successful upstream
CI run [38268479669](https://github.com/eez-association/eez-rollup0/actions/runs/38268479669).

The mixed workload completed 24 cross-chain operations in 13 accepted batches. The effect fixture has an
anchor and three effects. The anchor-only fixture contains ordinary L2 transactions. Every oracle comes
from an independent read-back: blocks from `debug_getRawBlock`, witnesses from `debug_executionWitness`,
calldata and proofs from successful mined L1 transactions, and the public inputs hash from the signer's
`window_signed` record matching the exact pre/post block hashes. The chain configuration is copied from
that devnet's genesis, including `feeCollector`. No expected hash or proof is computed by the code under test.

`rollupx/eezdev-699069` contains independently recorded public testnet data: genesis and the first fourteen
accepted batches, including L1 headers, logs, posting transactions, blobs and 2,251 L2 hashes (genesis through
block 2,250). The follower replay compares every derived block with those recorded hashes. The stateless
checks compare selected empty, deposit and ordinary-transaction blocks with the same independent hashes.

### Rollup0 live parent/time context

`captured-devnet-window-468/live-context-vector.json` is a separate derived unit
vector for Rollup0 #234 (`bf80de50fff74a549f1c34e07dbf66a9d27a28d3`). It uses
the unchanged block and witness bytes with selector `uint64.max`, an explicit
nonzero L1 parent and the executed terminal timestamp. Its expected digest was
computed independently with Foundry `cast keccak` using the upstream Solidity
and Rust encoding. The calculation reproduced both the original mined digest
and the upstream live-context shared hash vector. `cast wallet sign --no-hash`
with the existing public test key produced its expected signature.

This derived unit vector is not evidence of L1 acceptance. The original
`postbatch.hex` and `oracle.json` remain historical evidence. A signing test
requires the original system-bearing request to fail without live context.
Upstream conformance requests and expected outputs are replayed unchanged.
