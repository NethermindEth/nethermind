# Golden vectors

Generated by the C# persistence stack, replayed by the Rust persistence. One file per case:
`<layout>-<rlp|raw>-cf<0|1>.json`, for layout in Flat, FlatInTrie, PreimageFlatV1 and PreimageFlat, the slot
encoding, and carry-forward cache off or on. The op stream is the same for every case, except that ops the layout or
slot encoding rejects are left out: raw ops and account/storage range deletes in the preimage layouts, and
`setStorageRawEncoded` with raw slots.

Do not edit these files by hand. Regenerate them from `src/Nethermind` with:

```
dotnet build Nethermind.State.Flat.Rust.Test/Nethermind.State.Flat.Rust.Test.csproj -c release
dotnet test --project Nethermind.State.Flat.Rust.Test/Nethermind.State.Flat.Rust.Test.csproj -c release --no-build \
  -- --filter "FullyQualifiedName~Generate_golden_vectors"
```

`GoldenVectorTests.Checked_in_golden_vectors_match_the_csharp_persistence` fails when the C# persistence no longer
produces these files.

## Replaying

- Start from an empty database and, before the first step, write the slot encoding the C# side forces:
  Metadata column, key `keccak256("SlotEncoding")`
  (`0x09bb0de64c1d900d7ca4ea69e789fa38a9ce66a034cf43b99dd6e830c25566b7`), value `0x01` for `rlp` and `0x00` for `raw`.
- Then open the persistence and run the steps in order. `columns` is the sorted dump of every column after the step.
- A nonce or balance is its big-endian bytes without leading zeros, so zero is `0x00`. A slot, slot value or `tryGetSlot`
  value is 32 bytes. A `tryGetSlot`/`tryGetStorageRaw` miss reports value zero.
- In the preimage layouts the iterator and `tryGetStorageRaw` keys are the zero-padded address and the big-endian slot.
