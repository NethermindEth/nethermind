# Golden vectors

Generated by the C# persistence stack, replayed by the Rust persistence. One file per case:
`<layout>-<rlp|raw>-cf<0|1>.json`, for layout in Flat, FlatInTrie, PreimageFlatV1 and PreimageFlat, the slot
encoding, and carry-forward cache off or on. The op stream is the same for every case, except that ops the layout or
slot encoding rejects are left out: raw ops and account/storage range deletes in the preimage layouts, and
`setStorageRawEncoded` with raw slots.

Do not edit these files by hand. Regenerate them from `src/Nethermind` with:

```
dotnet build Nethermind.State.Flat.Rust.Test/Nethermind.State.Flat.Rust.Test.csproj -c release
dotnet test --project Nethermind.State.Flat.Rust.Test/Nethermind.State.Flat.Rust.Test.csproj -c release --no-build \
  -- --filter "FullyQualifiedName~Generate_golden_vectors"
```

`GoldenVectorTests.Checked_in_golden_vectors_match_the_csharp_persistence` fails when the C# persistence no longer
produces these files.

## Replaying

- Start from an empty database and, before the first step, write the slot encoding the C# side forces:
  Metadata column, key `keccak256("SlotEncoding")`
  (`0x09bb0de64c1d900d7ca4ea69e789fa38a9ce66a034cf43b99dd6e830c25566b7`), value `0x01` for `rlp` and `0x00` for `raw`.
- Then open the persistence and run the steps in order. `columns` is the sorted dump of every column after the step.
- A nonce or balance is its big-endian bytes without leading zeros, so zero is `0x00`. A slot, slot value or `tryGetSlot`
  value is 32 bytes. A `tryGetSlot`/`tryGetStorageRaw` miss reports value zero.
- In the preimage layouts the iterator and `tryGetStorageRaw` keys are the zero-padded address and the big-endian slot.

## Persisted snapshot tier

`persisted/<scenario>.json` are generated by the C# long-finality tier (`PersistedGoldenVectorGenerator`), for the
replay of the Rust tier. Regenerate them with the same build and:

```
dotnet test --project Nethermind.State.Flat.Rust.Test/Nethermind.State.Flat.Rust.Test.csproj -c release --no-build \
  -- --filter "FullyQualifiedName~Generate_persisted_golden_vectors"
```

`PersistedGoldenVectorGenerator.Checked_in_persisted_golden_vectors_match_the_csharp_tier` fails when the C# tier no
longer produces these files.

- Scenarios: `content` (every kind of entry, an empty snapshot, a table past 64 KiB whose index values take 3 bytes, reads
  under in-memory snapshots), `rollover` (shared, small and dedicated arenas, a small arena and a blob file rolling over),
  `merge` (windows of 2, 4 and 8, self-destruct barriers, deleted slots, references into two blob files, a large window
  sharing its bloom), `bloom0` (the `merge` steps with bloom bits per key 0) and `catalog` (a base from pre-genesis, rows
  the load skips, and a tier byte the load refuses).
- `config` holds the `IFlatDbConfig` values of the tier; the compaction offset is 0. The tier lives in
  `{base}/persistedSnapshot/{arena,blob}`, and the catalog is an in-memory key-value store.
- Steps, in order, from an empty directory and catalog:
  - `convert {from, to, records, estimate}`: a base converted from the snapshot holding `records` (the record stream of
    `flatdb-ffi/src/snapshot_stream.rs`); `estimate` is the size estimate the arena and blob writers were given.
  - `compact {to, persistedBlock}` and `compactSized {to}`: one compaction of the persisted compactor, run in the order
    its batch worker runs them after the base at `to` (a block whose window holds one snapshot is left out).
  - `reload`: the tier shut down (files of live snapshots kept) and loaded again; `error` instead of `state` when the
    load refuses the catalog, which ends the scenario.
  - `catalogPut {key, value}`: a row written straight into the catalog.
  - `reads {stackHead, committed, stack, inMemory, expect}`: a read-only bundle over the persisted snapshots assembled
    from `stackHead` down to `committed` (`stack`, oldest first, with their tier), under the `inMemory` snapshots (oldest
    first), over an empty persistence. Per address `getAccount`, `selfDestructIdx`, then `getSlot` with that index;
    then `loadStateRlp` and `loadStorageRlp` (a node of an in-memory snapshot, else the RLP loaded below it). A missing
    account, slot or node is `null`.
- `state` after a step: `catalog`, every row as `[key, value]` in key order; `files`, every file under
  `persistedSnapshot/` as `[path, length, sha256]` in path order; `snapshots`, per well-formed catalog row in key order,
  the snapshot the repository holds for it: the SHA-256 of its table (`table`), `blobRange`, `bloomCount` and
  `bloomDataBytes`. In `content` and `merge`, the step that first records a snapshot also carries its table
  (`tableHex`) and blob range (`blobHex`) when each is at most 16 KiB.
- The `merge` reads at head 2 return A's slot 4 before the large window exists and miss it after, where the bloom the
  large window shares with the windows it holds lacks the slots its merge dropped below A's self-destruct; `bloom0`
  returns it in both. The miss is a probable C# bug: a bloom shared across a range is no superset of the snapshots it
  is shared with once a merge drops keys below a self-destruct barrier. The vectors pin it on purpose, so the port stays
  faithful to C#; a fix in C# has to be ported and the vectors regenerated.
