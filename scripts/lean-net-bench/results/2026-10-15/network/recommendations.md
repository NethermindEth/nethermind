# Specification recommendations

Based on all 84 immutable V12 attempts (two per configuration), with [raw data, scope and source identities](README.md). These support retaining tested settings for continued implementation testing, not selecting universal optima or changing consensus bounds.

## Provisional numerical settings

Retain these existing values for continued implementation testing pending broader and adversarial validation. They are not optima selected by a parameter sweep. Wire ceilings are interoperability rules; the lower implementation defaults are separate.

| Category | Suggested setting | Basis and condition |
| --- | --- | --- |
| EIP-8437 wire geometry | Retain 64 KiB chunks, at most 32 chunks/request and four requests/direction/peer | The campaign tests this combination, not alternatives; the 16-transaction 8 objects/s point completed 2/2 for both bindings at both 50/200 ms; higher rates can be incomplete |
| Object interoperability | Retain the 9 MiB object ceiling, accommodating an 8 MiB proof | Do not reduce a wire ceiling because ordinary roots are much smaller; require maximum-object delivery and recovery to remain functional |
| Unvalidated-byte ceilings | Retain 18 MiB/source and 72 MiB/global; allow lower local refusals as the spec does | Account body, decoded proof, recovery, parser/QUIC buffers and retained completion owners; these bytes are not a process/native RAM cap |
| Local QUIC credit | Retain 512 KiB/connection and 2 MiB/stream pending matched-window experiments | Preserves maximum-object headroom in the 18 MiB source budget. Long-RTT behavior may motivate a future tested rebalance, not a blind credit increase |
| Local recovery pipeline | Retain four global recovery workers, at most four ETH recovery requests per peer, 16 envelopes/batch and eight queued validations | The eight-queue limit excludes the at-most-four active workers. Proof verification/admission remains serialized; workers release that gate while awaiting ETH. These defaults need backlog/fairness evidence as well as successful delivery |
| Local announcement/assembly buffering | Retain 64 deferred announcements/source, eight active assemblies/source and 32 globally | Finite bursts may shed work under overload. Report missing counts; do not infer infinite backlog or guaranteed delivery of every announcement |
| Local validated-object retention | Retain 256 objects / 128 MiB | The 384-object high-load cohorts exceed this count ceiling. Serving availability and receiver buffering are separate confounds; this is not the 256-dependency native proof limit |
| Request/source lifetimes | Retain three source attempts; request idle/absolute 30/120 s; assembly idle/absolute 30/300 s | Short honest runs do not establish optimal deadlines. Serving an available object does not request proof generation |
| Ethp2p profile ceilings | Retain 1 MiB bodies, 16 data + 16 parity shards, at most 16 live shard streams per peer connection and four sessions globally per node engine | Completion includes retrieval fallback; pair measurements do not establish broad fanout resilience or a per-RTT byte guarantee |
| Aggregation scheduling | Retain a 1 s scheduling cadence, not a 1 s completion deadline | Cold native observations exceed one second for larger sets and parent merges; evaluate reuse, coalescing and producer priority separately |
| Dependency acceptance/pricing | Keep draft 4096 and generic weight 16 explicitly provisional; the captured guest's executable limit remains 256 total/16 generic | Do not activate a 4096 consensus ceiling using a 256-capacity guest. No replacement weight or gas number is justified by a trivial generic fixture or transport goodput |

For the next controlled 16-transaction, roughly 296 kB-wrapper pair tests, start at **8 objects/s** under the tested 100 Mbit/s, 50/200 ms, zero-injected-loss conditions: all corresponding cohorts completed. This is an operational test point, not a protocol rate requirement or fresh-signature production budget. At 50 ms RLPx also completed 2/2 at 32/s for 1/16 transactions, whereas QUIC one-transaction 32/s varied from 110/192 to 192/192. At 200 ms both bindings were incomplete at 32/s. Keep observed ranges and completion counts, not a single steady-state ceiling.

The six-second release windows include startup/ramp effects; full-window goodput retains drain and missing-object waits. A tested complete point is an operating observation, not maximum sustained capacity. Larger transaction counts also require more ETH recovery batches and transaction handling. Both 8 MiB proof-size cohorts completed per binding/repetition, supporting continued maximum-object interoperability tests rather than a lower ceiling. Do not interpret their differences as per-signature native costs. Keep recommendations about local defaults separate from normative encoding and acceptance limits.

## Native activation evidence

The [existing native capture](../../2026-10-14/native/README.md) demonstrates real mixed recursion and supplies realistic proof-size anchors. It uses an Apple M2 Max/32 GiB host, one worker, three small-case samples and one exploratory SPH64 sample; managed work overlapped part of capture. Prepared-parent merge excludes preparation. Process RSS observations are not upper bounds.

The generic fixture is a trivial real 2048-instruction program, not worst permitted μ22 code. These measurements do not establish a universal generic dependency weight of 16, price worst-case gas or demonstrate the draft 4096-dependency ceiling: the captured guest supports 256 total dependencies. Activation evidence needs every accepted geometry and mixture, exact coverage/discards, worst legal generic work, and RAM/latency tails under the intended hardware budget.

One-second aggregation cadence is a scheduling opportunity, not demonstrated one-second proof completion. Root reuse, bounded/coalesced background work and producer priority should be evaluated separately from sustained fresh-claim proving. This campaign performs no Lean compiler or prover tuning. Serving an already available object must not be assigned a proof-generation timeout from cold native timings.
